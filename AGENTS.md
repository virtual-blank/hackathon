# AGENTS.md

Инструкции для AI-агентов (Claude Code и др.). Проект — трекер привычек с
соцсетью: друзья, чат, общие привычки, достижения, уведомления в Telegram.


## Как себя вести агенту

- **Объясняй причину и называй вещи общепринятыми терминами** (транзакция,
  N+1, идемпотентность, DI). Предлагаешь правку — скажи, что сломается, если
  оставить как есть. «Так принято» — не причина.
- **Простое решение лучше универсального** (KISS, YAGNI). Не добавляй базовые
  классы, новые слои и паттерны «на вырост»: абстракция появляется, когда есть
  второй настоящий потребитель.
- **Пиши так же, как написан соседний код.** Образец домена — `src/users/`.
- **Чужой код без просьбы не переписывай.** Правила ниже — про новый код.
  Заметил проблему в чужом домене — скажи о ней, а не чини.
- **Различай «сломается» и «можно лучше».** Первое — исправляем сейчас. Второе
  — называешь один раз с объяснением, решение остаётся за автором.
- **Не уверен в API библиотеки — посмотри документацию**, а не вспоминай.
  Точные версии — в `backend/poetry.lock`.

## Стек и структура

Python 3.12 · FastAPI · SQLAlchemy 2 (async, asyncpg) · PostgreSQL · Alembic ·
Pydantic 2 · Poetry.

```
backend/
  main.py            точка входа FastAPI, регистрация роутеров
  core/config.py     настройки (pydantic-settings)
  database/          Base, сессия, миксины, str_enum
  alembic/           миграции
  ruff.toml          настройки линтера и форматтера
  src/
    auth/            JWT, хеш пароля, зависимости (SessionDep, CurrentUserDep)
    exceptions/      исключения приложения
    {domain}/        users · habits · social · analytics · telegram
frontend/
.githooks/           git-хуки (подключаются через make hooks)
Makefile             команды разработки
docker-compose.yml
```

Корень импортов — `backend/` (`from src.users...`, `from core.config...`,
`from database.db...`). Настройки читаются из `.env` в корне репозитория.

## Команды

Запускаются из корня репозитория; полный список — `make help`.

| Команда | Что делает |
|---|---|
| `make install` | установить зависимости |
| `make hooks` | подключить git-хуки — один раз после клонирования |
| `make run` | запустить API-сервер |
| `make lint` | проверить код линтером, ничего не меняя |
| `make fix` | исправить то, что линтер чинит сам |
| `make format` | отформатировать код |
| `make migrate` | применить миграции |
| `make migration m="..."` | создать миграцию по изменениям моделей |
| `make lock` | пересобрать `poetry.lock` после ручной правки `pyproject.toml` |

**Перед коммитом:** `make lint` — в файлах, которые ты менял, замечаний быть
не должно. Форматирование делает pre-commit хук: он прогоняет `ruff format` по
файлам коммита. `make fix` и `make format` работают по всему `backend/` и
переписывают в том числе чужие файлы — в свой коммит их результат по чужим
доменам не добавляем.

## Правила

### Архитектура

1. **Три слоя: `router.py` → `service.py` → `repository.py`.** Роут разбирает
   запрос и выбирает ответ, сервис принимает решения, репозиторий ходит в БД.
   Зависимости идут только вниз: репозиторий не знает про сервис, сервис — про
   HTTP.
2. **Структура домена** в `backend/src/{domain}/`: `router.py` · `service.py` ·
   `repository.py` · `schemas.py` (Pydantic) · `models.py` (SQLAlchemy) ·
   `enums.py`.
3. **Роут тонкий:** разобрать вход → вызвать сервис → вернуть схему. Условий
   и расчётов в нём нет — иначе логику не переиспользовать и не проверить без
   HTTP.
4. **Зависимости приходят снаружи (DI).** Сессию роут получает через
   `SessionDep`, передаёт в сервис, сервис — в репозиторий. Текущий
   пользователь — `CurrentUserDep` / `CurrentUserIdDep` из `src/auth/deps.py`.
5. **Домены не лезут в чужие таблицы своими запросами** — зовут репозиторий
   или сервис того домена. Иначе изменение таблицы ломает код, о котором её
   владелец не знает.
6. **Одинаковый код в трёх местах выносим в общую функцию** (DRY). В двух —
   ещё рано: неизвестно, что в них действительно общее.

### Python

1. **Аннотации типов обязательны** у параметров и возвращаемого значения.
   Синтаксис `list[X]`, `X | None`.
2. **Pydantic — на каждой границе:** тело запроса, ответ, ответ внешнего API.
   Сырой `dict` между слоями не передаём — у него нет контракта.
3. **ORM-модель → схема** — `Schema.model_validate(orm_obj)` при
   `ConfigDict(from_attributes=True)`, а не перекладывание полей руками.
4. **Схема — минимум полей.** Значение, которое выводится из других, —
   `@computed_field` / `@property`, а не отдельное поле.
5. **`async` — только когда внутри есть `await`.** И наоборот: в
   `async`-функции нет блокирующих вызовов — `httpx`, а не `requests`;
   `await asyncio.sleep`, а не `time.sleep`. Блокирующий вызов останавливает
   event loop, и сервер перестаёт отвечать всем.
6. **Понятные имена, без односимвольных:** `habit`, а не `h`. Поле —
   существительное (`pending_items`), булево — предикат (`is_read`).
7. **Число или строка, по которым принимается решение, получают имя:**
   `if streak >= WEEK_STREAK`, а не `if streak >= 7`.
8. **Функция не возвращает безымянный кортеж** вроде `tuple[User, list[int]]`.
   Больше одного значения — схема или dataclass с именованными полями.
9. **Модуль называется по содержимому.** `helpers.py` / `utils.py` /
   `common.py` превращаются в свалку.
10. **Настройки** — класс `BaseSettings` с `env_prefix` в `core/config.py` и
    фабрика `get_<name>_settings()` под `@lru_cache`. Секреты — только из
    `.env`, который не коммитим.
11. **`logging` вместо `print`.** В `except` — `logger.exception(...)`: он
    пишет стек.
12. **Комментарий объясняет, почему так,** а не пересказывает код.
13. **`# noqa` и `# type: ignore` — только с объяснением рядом,** почему
    правило нельзя выполнить.

### База данных

1. **Запросы к БД — только в репозитории.** Никаких `select` / `insert` /
   `update` / `delete` в сервисах и роутах.
2. **Без сырого SQL** (`text("SELECT ...")`) — SQLAlchemy expression language.
   Значения в запрос никогда не подставляем форматированием строк: это
   SQL-инъекция.
3. **Одна бизнес-операция — одна транзакция.** Проверку и запись, которые
   должны быть атомарны («заявки ещё нет → создать заявку»), не разносим по
   разным `commit()`.
4. **Связи в async не подгружаются лениво.** Обращение к `user.habits` без
   явной загрузки падает с `MissingGreenlet`. Нужна связь — `selectinload` /
   `joinedload` в запросе. Запрос в цикле по списку — это N+1: загружаем одним
   запросом.
5. **ORM-модели** наследуют `Uuid7PkMixin, TimeStampMixin, Base`: `id`,
   `created_at`, `updated_at` приходят сами. `__tablename__` — snake_case,
   множественное число. Nullable выражается типом: `Mapped[int | None]`.
6. **Типы колонок:** `String(n)` с длиной, `DateTime(timezone=True)` всегда,
   enum — через `str_enum(...)` из `database/enum.py`.
7. **Имена ограничений и индексов руками не задаём** — их генерирует
   `NAMING_CONVENTION` в `database/db.py`.
8. **Идентификатор внешней системы — не первичный ключ.** `telegram_chat_id`
   лежит отдельной колонкой с `unique`; внешние ключи идут по нашему `id`.
9. **Индекс — под конкретный запрос.** Каждый индекс ускоряет чтение и
   замедляет запись.
10. **Не храним вычисляемое** — `@property`, а не колонка: иначе значение
    разойдётся с исходными данными.
11. **`NULL` в уникальном ограничении дублей не ловит:** в Postgres
    `NULL != NULL`.
12. **Миграции — только `make migration m="..."`.** Созданный файл читаем:
    изменение попало, лишнего нет, данные не теряются. После слияния веток
    проверяем, что head один. Новый `models.py` импортируем в `alembic/env.py`
    и `main.py`, иначе автогенерация его не увидит.

### API

1. **REST:** путь — ресурс (существительное, множественное число), действие
   задаёт HTTP-метод. `GET /habits` · `GET /habits/{id}` · `POST /habits` ·
   `PATCH /habits/{id}` · `DELETE /habits/{id}`.
2. **Вложенный ресурс** — `GET /habits/{id}/logs`. Фильтры, пагинация и
   сортировка — в query-параметрах.
3. **Действие, которое не ложится на CRUD, оформляем как ресурс:** отметка
   выполнения — `POST /habits/{id}/logs`, а не `/habits/{id}/complete`.
   Исключение — аутентификация (`/users/login`).
4. **Статус-код соответствует результату:** `201` на создание, `204` на
   удаление без тела, `404` — нет ресурса, `409` — конфликт состояния, `422`
   — невалидный вход (его ставит FastAPI).
5. **Вход и выход — схемы из `schemas.py`**, `response_model` указан. Наружу
   не отдаём ORM-модель и поля вроде `password_hash`.
6. **Список всегда ограничен:** `limit` с верхней границей или курсор.

### Ошибки

1. **Сервис бросает исключение**, а не возвращает `None` / код /
   `{"error": ...}`. Свои типы ошибок — классы в `src/exceptions/`.
2. **Сервис не бросает `HTTPException`** — HTTP не его слой. В статус-код
   исключение переводит роут.
3. **Внутри `except` пишем `raise NewError(...) from exc`** — иначе теряется
   исходная причина.
4. **Ловим конкретный тип, а не `Exception` «на всякий случай».** Голый
   `except:` и `except BaseException` не пишем: они глотают отмену задачи и
   остановку процесса.
5. **Текст ошибки для пользователя — без внутренних деталей.** На неожиданную
   ошибку (500) — нейтральное сообщение, не `str(exc)`.
6. **Побочный эффект не роняет основную операцию.** Не ушло уведомление в
   Telegram — пишем `logger.exception` и продолжаем.

### Тестирование

1. **Основной вид теста — интеграционный, через API-роут.** Он проверяет код
   так, как его зовут на самом деле, и не ломается при перестановке
   внутренностей. Unit-тест — для чистых расчётов (стрики, достижения).
2. **Проверяем результат, а не вызовы:** что вернулось и что легло в БД, а не
   «сколько раз позвали метод».
3. **Настоящий Postgres, не sqlite** — у них разные ограничения и семантика
   `NULL`.
4. **Роуты тестируем через `httpx.AsyncClient` + `ASGITransport`**, не
   `TestClient`: тот запускает приложение в другом event loop.
5. **Тест читается сверху вниз:** подготовка → действие → проверки.
   Дублирование в тестах лучше хитрых хелперов.
6. **Красный тест в репозитории не оставляем.**
